# v1.2.6 alignment and compare validation

## Implemented contract

- Landmark edits are private drafts. Candidate failure or point deletion clears candidate validity, not the committed transform. Done, Enter, Align re-click and pane Done messages share `commitLandmarkEdit` and require four valid pairs for every member.
- Commit validates the captured group/session, epoch, membership, pane instance, local context, landmark revisions, reflection policy and committed revision before publishing all pairs together. Layout-only synchronization does not prevent Done.
- Cancel, Escape and Stop discard the draft and invalidate pending spatial work. Hiding the toolbox preserves the group, draft and any pending transaction.
- Keep mirror state is the default. Infer mirror requires non-collinear geometry. Limited landmark coverage is advisory, independent of mathematical validity. Views keep their committed transform until Done.
- Clear Points affects the draft only. Reset Orientation and Remove Fit are separate operations. Remove Fit retains manual orientation and rematches the captured centers.
- Landmark editing locks the toolbox height for the edit and viewport width. Point counts, candidate failure, RMS and warning text cannot resize the slide panes mid-placement. Hide/reopen preserves the lock; actual window-width changes may remeasure it.
- Active linked slide owns orientation controls, anchor-origin arrow nudges and the displayed offset. Member-origin nudges target that member.
- Keyboard nudges use measured source-pixel deltas and a serialized queue, not differences between independently updated viewport centers. Accepted adjustments relay the adjusted pane's current zoom. Option-drag accumulates actual drag movement, excludes zoom-induced center changes, and suppresses drag-end flick; stale replies cannot alter either viewport state or the transform.
- All spatial operations require focused, ready contexts throughout the group. A plate grid has no implicit site-0 alignment target. Source/site changes invalidate local commands immediately; T/Z share the same site-owned spatial context.
- Requests freeze their target list and context envelopes. Responses remain transaction-local until completion; canceled/unknown responses never become user viewport events. Reload retires the old pane instance; unready images cancel capture work.
- The pane has one latest-command slot and one OSD-open listener. Session/epoch, pane instance, context, spatial enablement and command sequence are revalidated at receipt and application.
- Fitted transform and member-space manual offset are separate. Fit RMS and Current RMS use the stored point provenance. Inversion transforms the offset and swaps landmark-set/point ownership. Memory is keyed by source-generation/site contexts and written only for explicit committed changes, not toolbar rendering.
- A mismatched stored landmark set remains a labeled stored transform; it does not become a valid current fit by reopening Align.
- Physical mappings use `D_member^-1 * similarity * D_anchor`. Rendering requires normalized Gram anisotropy error at most `1e-10` (a numerical-roundoff tolerance). Unsupported anisotropic mappings are blocked, never silently presented as exact micrometer linking. Relative mapping is an explicit display-only choice.
- ROI and box previews project the final clipped source rectangle. Outward integer edge rounding happens once, with sub-`1e-7`-pixel noise snapping. Preview, final rectangle and raw export bounds agree, including arbitrary rotation and reflection.
- The scalebar maps a horizontal CSS-screen displacement back to source coordinates and applies both X/Y pixel sizes. No device-pixel-ratio multiplication is involved. Unknown calibration does not produce a physical scale.

## Automated coverage

Production JavaScript is exercised by Node-based regression tests, including fake timer/message queues rather than only static source checks. Coverage includes stale and canceled replies, frozen transaction membership, atomic commit, clear/cancel/stop, site round trips, pane reload, delayed OSD open, mirror constraints, inverse fit provenance, arbitrary-angle and anisotropic mappings, and ROI/export/scalebar agreement over rotation, reflection, clipping, zoom, resize and DPR.

The full Python suite also exercises ND2 reads/exports, plate cache integrity, annotations, calibration, server endpoints and existing trackpad routing. Release CI must be green for the exact tagged source SHA; packaged and installed app smoke checks and signed updater-asset validation remain required.

Final local run: **522 passed** in 56.43 seconds, with 122 upstream ND2/NumPy deprecation warnings and no skipped tests. Ruff, JavaScript syntax checks and whitespace checks passed. CI explicitly installs Node 22 so the JavaScript regression modules cannot silently skip because the runtime is missing.

## Scope and limitations

- The display renderer remains a rotation/reflection/uniform-scale renderer, not an arbitrary affine or nonlinear registration engine. Explicit Relative mode does not claim physical registration.
- A low landmark RMS does not establish same-cell correspondence between serial sections or globally accurate registration away from the landmarks.
- Original slides, scientific annotations and existing research caches are not modified by the validation workflow. QA annotation destinations are disposable temporary files.
- Native physical-trackpad behavior is unchanged in this patch. Synthetic input and unit tests are not evidence of a new hands-on physical-trackpad trial.
- Developer ID notarization is not added here; GitHub distribution and the independently signed Sparkle update path continue.

## Release checks

Interactive checks use a separate local registry with read-only real H&E/MT and four ND2 sources; annotation destinations are temporary. The user's manually aligned session is kept running separately and is never reset by these tests.

- H&E/MT transpose changed only the member display; Reset restored its manual orientation.
- A geometric four-point test produced an arbitrary 37-degree fit. These deliberately non-corresponding QA points were not a tissue registration result.
- A separate approximate corresponding-tissue test produced a -3-degree fit with 145 micrometer RMS. This checks the workflow, not scientific correspondence accuracy; the user's independent -5-degree, 31.8 micrometer fit was left untouched.
- During four-point placement in the isolated session, toolbar bounds stayed `(170,52,940,210)` and both visible pane bounds stayed 640 by 448 CSS pixels at y=272, before and after candidate completion.
- Clear Points invalidated Done while the committed Fit RMS and Current RMS remained visible. Cancel restored the previous points and left both residuals unchanged. Toolbox X preserved the link and fit.
- In a fresh isolated final-code session, clicking to zoom followed immediately by Right preserved the new 1.9 percent display zoom, without a spurious Y offset. At the settled zoom, each Right added approximately 26.2 micrometers in X; three rapid Right presses added approximately 78.6 micrometers. Automated tests additionally cover stale anchor zoom/center, revision changes, cancellation, reflected arbitrary-angle transforms and actual-delta Option-drag.
- A rotated ROI displayed a slanted source-aligned footprint and final integer bounds of 23,837 by 12,073 source pixels. Automated tests cover the shared raw-export bounds without exporting the large real-data ROI.
- Independent source preservation check: all six source quick fingerprints and 2,334 existing cache-file size/mtime entries matched their pre-QA snapshots; no original annotation changes.

### Performance observations

A same-machine Node 25.8.1 microbenchmark compared v1.2.5 commit `e459ced7` with the pre-final-nudge v1.2.6 relay code. Five alternating repeats used 2,000 warmup and 10,000 direct pan relay calls. Two-pane median/p95: 1.084/1.208 microseconds before, 8.292/8.916 after. Four-pane median/p95: 2.792/2.958 before, 22.125/24.750 after. Both emitted the same 10,000/30,000 commands and performed zero residual recomputations or fits. Correctness gates add CPU work; this is not a speed-improvement claim and excludes rendering, networking and physical input.

An early mixed cold/warm real-UI sample of 82 successful tile GETs had p50 2.667 ms, p95 53.645 ms and maximum 124.243 ms; peak server RSS was approximately 255.4 MiB. It is not a controlled before/after playback benchmark. The only observed HTTP error was a harmless favicon 404, not a slide or tile error.
