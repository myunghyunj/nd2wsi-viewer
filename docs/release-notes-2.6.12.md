# nd2wsi-viewer 2.6.12

This patch release accelerates `.nd2svs` pyramid cache creation and single-file conversion through direct-to-SQLite chunk writing and sequential Level-1 ND2 overview streaming, while preserving exact pixel parity and full format compatibility with 2.6.10 and 2.6.11.

- **Direct-to-SQLite `.nd2svs` pyramid writer.** Write Zarr v2 metadata and Blosc-compressed (`zstd`, level 3, bitshuffle) pyramid tiles directly into a single staging SQLite container in bounded batches instead of staging thousands of loose chunk files and repacking them afterward. Retains producer-side coordinate accounting (including omitted all-zero tiles), byte-bounded `rowid`-ordered SHA-256 verification on a reopened read-only handle, post-first-level source-mutation fast-fail checks, bounded Windows staging retries, and safe cleanup of interrupted `.building-*` and rollback `-journal` pairs. Cuts temporary disk usage in half (~50% lower peak staging bytes) and speeds up full (`overview=False`) single-file builds while keeping the `nd2svs-sqlite/2` / `nd2wsi-cache/4` container format unchanged.
- **Channel-coherent sequential ND2 Level-1 overview reader.** Stream uncompressed interleaved `uint8`/`uint16` ND2 planes sequentially via double-buffered OS reads with balanced multi-pass channel grouping when building `overview=True` viewing caches, failing closed automatically to the existing Dask path on compressed, legacy, multi-Z projection, or non-standard layouts. On 14–17 GiB four-channel `uint16` ND2 scans on external exFAT SSDs (Apple silicon macOS), end-to-end verified overview cache creation improves **5.7×–6.9×** (`155.6–207.3 s` → `22.6–36.2 s` across `exFAT → APFS` and `exFAT → exFAT`) with **~72–75% lower peak RSS** (`6.8–7.5 GiB` → `~1.9 GiB`), bit-identical `box-mean-floor-v1` pixels at every stored level, and identical OMERO display windows.
